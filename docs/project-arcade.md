# Project arcade

Six compact games turn a project's engineering decisions into actions, constraints and visible outcomes. The default green homepage remains at `/`; the optional Arcade view stays at `/play`. Tap a cabinet or use arrow keys and Enter to open its screen. A native modal dialog keeps the working game near the top, contains focus, and makes the floor inert. Back to arcade, Escape and browser Back exit; progress stays in the same live DOM and focus returns to the selected cabinet. Direct `#concept-project-slug` links open a cabinet. The room supports mobile scrolling and reduced motion.

## Games and references

All interfaces, artwork, fixtures and game code are original. The references below supply recognizable mechanics, not copied assets or levels.

| Project / game | Mechanic reference | Play | Engineering connection |

| Bakiano / Basket Run | [Grocery Game](https://cbs.priceisright.com/game-page/?id=grocery-game) | Drag groceries or use Add to fill four exact orders under budget, stock and basket-space limits. Shared delivery fees complicate store choice. | Normalize pack sizes and currencies; reject stale observations and mismatched rate dates. |
| GCP Ingestion Lab / Packet Factory | [Infinifactory](https://www.zachtronics.com/infinifactory/) and [Human Resource Machine](https://tomorrowcorporation.com/humanresourcemachine) | Build a spatial conveyor factory across five shifts. Route fresh packets through machines and duplicates into a separate return bin. | Completed receipts avoid duplicate work, observation time beats arrival order, and receipts must follow successful commits. |
| Catalog Match Lab / Catalog Customs | [Papers, Please](https://papersplea.se/presskit/) | Two stamp tutorials, then six lineups of 3–8 near-identical products. Pick the verified match or none. | BigQuery Query Guard / Partition Sweep | [Opus Magnum](https://www.zachtronics.com/opus-magnum/) | Produce an exact output while shrinking a grid's read footprint to fit a budget. | Projection and partition filters reduce reads; LIMIT alone does not. |
| Image to Pixels / Pixel Shuffle | Picture-tile puzzles | Tap two tiles to swap them; later pictures add rotated pieces. Five original illustrations progress from 2×2 to 4×4. | The pinned renderer creates the actual puzzle pictures; wins compare pixels rather than tile IDs. |
| Vesti / Complete the rack | [SET](https://playmonster.com/product/set/) | Complete a three-card rack where each attribute is all the same or all different; two tries per rack. | Multiple independent attributes must be checked, rather than treating overall resemblance as identity. |

The six games contain 28 authored stages in total: Basket 4, Factory 5, Customs 8, Query 3, Pixel Shuffle 5 and Garments 3. Each has explicit instructions, results, inspection evidence and replay/reset. Stages are intentionally compact; they connect a small playable problem to the project behind it.

The Arcade appearance also adds an optional **Experience platformer** to `/timeline`. Its blinking Play button starts a manually controlled platformer using the same original SVG player as the project floor. The real chart bars keep their company names, category, position, width, height and lane. Jump through a bar from below and land on top; left/right movement lets visitors explore either direction. Extra unlabeled ledges create high and low routes, with diamonds to collect and red spikes to avoid. Landing on a real role saves a checkpoint; a spike hit returns there while keeping collected diamonds and visited roles. Further ledges continue beyond the career chart without inventing career history. Arrow keys or A/D move, Space/Up jumps, Down crouches, and Down + jump drops through a platform. Equivalent touch controls support simultaneous movement and jumping. Pause/resume, restart, Exit/Escape, tab/visibility/resize pausing and a local best score are included. Exit restores the clickable chart and its scroll position. Reduced motion disables decorative blinking and walking animation; gameplay never starts automatically.

A small **lava flow enters from the left** after a six-second head start. It advances along the ground in world coordinates, gradually becoming taller and faster. Only the area behind its leading edge contains lava; the ground ahead stays clear. The shallow leading edge is a real slope that can be jumped over, with rendering and collision using the same geometry. Height and speed are capped, and running remains faster than the lava. Its orange surface has slow molten texture movement, disabled by reduced-motion preferences. Pause freezes both the flow and its growth. Retry moves a small flow behind the last checkpoint and restores the head start while preserving diamonds and role progress. There are no notification cards or snooze controls. Added platforms remain unlabeled.

## What actually runs

**Catalog Customs** calls the pinned public repository's `compareNames` function for every verdict. The expected answers are computed from its output. Its 35 fictional declarations cover six product kinds. Seeded replay shuffles positions; one lineup deliberately has no verified match. Every submitted inspection exposes an audit of every candidate, including conflicts and uncertainty. Unknown qualifiers remain uncertain. This is neither a trained model nor Bakiano's private production matcher.

**Pixel Shuffle** replaces the image-processing recipe controls with a direct picture puzzle. Five original 96×96 illustrations become 48×48, six-color images through the unchanged renderer, using nearest color, error diffusion or ordered dithering. The game then scrambles them into 2×2, 3×3 or 4×4 tiles. Two taps swap pieces; stages 3–5 introduce rotation. Completion is automatic, undo is free, and exceeding the optional move goal never locks play. A seeded reshuffle keeps every piece and remains solvable. Winning compares each tile’s actual RGBA pixels with the target, so visually identical pieces are interchangeable. Tile gameplay is original puzzle code, not a claim that the upstream renderer is a game engine. Source and rendering evidence sit in a collapsed panel.

The previous unrestricted product-name inspector and worker-backed image A/B comparison remain in expandable sections under their games. The image comparison still holds source, grid and palette constant, ignores stale worker responses and compares bytes when checking repeatability.

**Packet Factory** is a deterministic teaching model of the public ingestion repository's receipt/read/merge ordering, not an embedded GCP loader. Packets traverse a 7×5 board; gaps, obstacles, cycles and incorrectly ordered machines fail at the actual tile. A receipt gate routes fresh packets forward and duplicates right. Reads and attempted merges count operations in this model, not cloud jobs, timing or billing. Blackout and Rush hour inject a failure before commit. The run pauses when its cabinet or browser tab becomes hidden. Building is available through buttons and keyboard controls; dragging is not required.

**Partition Sweep** is an executable column-store simulation, not the Query Guard, a SQL interpreter or live BigQuery. Tile costs are fictional units. Product remains a read dependency for ordering even when omitted from the output. Dates are partition metadata. The UI separates this model from the repository's recorded measurements and links their source. Compression, clustering, cache effects and billing minimums are outside the model.

**Basket Run** uses synthetic grocery offers, amounts, dates and exchange rates. Simulated market dates are fixed at 16 or 17 October 2026, never presented as today's real market. Offers normalize into integer cents and base units; delivery is charged once per store. Each market has exactly one feasible basket across all stock-bounded combinations. Conversion uses the rate attached to an observation; an eligible VES observation needs a rate with the same date. The game illustrates the public Bakiano case study without exposing private source or data. Drag/drop is optional; Add and Remove offer the same mechanics by touch or keyboard.

**Complete the rack** uses explicit shape/color/pattern tags and original SVG garments. It does not run Vesti's segmentation or retrieval pipeline and makes no claim about AI quality. Its connection is attribute reasoning; a real image-based Vesti demo still requires actual saved model outputs and provenance.

## Source provenance

`public/play/sources.json` records each embedded engine's repository, exact commit, source path and LF-normalized SHA-256. Engine copies remain unchanged apart from the matcher's `.js` → `.mjs` filename. Its MIT notice accompanies the source. The interface links to exact revisions; snapshot tests detect drift. Review upstream changes and update the manifest before replacing an engine.

## Verification

Appearance is a site-wide browser preference saved in the first-party `portfolio_view` cookie for one year. Picker links use `?view=original|tech|arcade`; the server saves the choice and redirects to a clean URL. Ordinary navigation never changes it, including project case studies, Timeline, List view, games and Home. First visits infer a default from the entry page; returning visits use the saved choice. Rendering happens before the first paint and works without JavaScript. HTML is private and not cached, keeping preferences separate between visitors. Restoring a history page with an outdated appearance reloads that page; matching pages preserve their live state. The screen themes leave the print stylesheet unchanged.

Run `npm test` and `npm run typecheck`. Tests cover exhaustive basket feasibility, picture-puzzle and reshuffle solvability, renderer outputs, spatial routing, duplicate and failure behavior, dated price rejection, unknown matcher attributes, finite attempts, replay state and pinned source integrity. DOM interaction tests use the shipped markup and event listeners to play every stage, check failure paths, reset and keyboard focus. Dialog tests check opening, closing, focus restoration and progress preservation. Canvas calls are captured in those tests; separate renderer tests verify real pixel buffers. DOM tests do not measure layout or replace visual browser checks.

Browser checks should exercise wrong and correct moves, advancing/resetting, keyboard focus, station switching, narrow layouts and the two free inspectors. Platformer tests cover real-bar geometry, one-way landings, manual movement, hazards, checkpoints, drop-through, a playable generated route and keyboard/touch controls. Lava tests cover the small start, head start, horizontal advance, gradual growth, speed limits, sloping collision boundary, pause and checkpoint reset. DOM tests exercise its visible extent, camera tracking, warning and retry message at narrow and wide viewport dimensions. No account, paid API, cloud query or analytics is introduced. The appearance preference and platformer best score stay in the visitor's browser. Without JavaScript, project descriptions, limitations and reading links remain available.

### Short walkthroughs

- **Basket:** B×2 + D + E ($8.80); B + D + F ($9.90 including delivery); A + B×2 + C + D + E ($9.30); D×3 + E + G ($10.10 including delivery). Each next market has a distinct title, brief, shelf and constraints.
- **Factory:** first shift C2 Read→, D2 Latest→, E2 Stamp→. Return lane B3 Gate↑, C3 Belt↓, C4 Belt←, B4 Belt↓. Late truck D2 Latest→. Blackout replace D1/E1 with Latest→/Stamp→. Rush hour uses the upper corridor plus a separate lower return lane; full recipes are in the routing/control tests.
- **Customs:** Approve, Hold, then declarations ML-1, RC-1, FL-1, CF-1, none, BR-1. Shelf positions change on replay; inspect names and evidence.
- **Query:** stage 1 deselect Notes and Image; stage 2 also deselect 14/15 October; stage 3 use the same footprint with an output limit of one.
- **Pixel Shuffle:** use the reference image to put pieces in place, then turn sideways pieces upright. Two taps make a swap; R or Turn tile rotates a selected piece. Moves beyond the goal still count as a win. Shuffle again changes the arrangement.
- **Garments:** choose cards 3, 5, then 1.
